# Overview of Scripts 
Scripts accomplish different parts of the ML pipeline, here we quick annotate behavior and cofniguration file formats.

1) generate\_training\_data.py
	- 
	- Behavior:
		- Generates a series of .npy files containing black (0) and white (255) pixel values on a canvas. 
		- An annotations file is generated labeling each .npy file with statistics about the image. 
	- Config fmt:
		```python
		CONFIG = {
        	"fill_frac" : [0.1, 0.01, 0.3, 0.5, 1], 
			#^ Density of pixels in negative space
        	"max_N_to_try" : list(range(0,200)), 
			#^ Number of attempts inserting circle images
        	"samples_per_setting" : 50, 
			#^ Number of different images per hidden param set
        	"data_root_filepath" : "raw_data",
			 #^ Where to save the .csv and samples/.npy folder
		}
		```
		(See default example -> src/generator/default_config.py)

2) scrub\_and\_split.py
	- 
	- Behavior:
		- Reads raw annotations file generated by script #1, examines each pixel image for duplicates. Prints list of duplicates to a seperate annotations file before dropping them from a dataframe
		- Writes a new annotations file without duplicates, with images shuffled and assigned a split "train", "val", or "test" according to the fractions passed in the config file

	- Config fmt:
	```python
	CONFIG = {
        "raw_rootpath" : "raw_data", # Location of data we're cleaning up
        "raw_annotations" : "combined_raw_annotations.csv",
        "train_frac" : 0.6,
        "val_frac" : 0.2,
        "test_frac" : 0.2,
        "scrubbed_rootpath" : "final_data" # Location of trim logs and final annotations list
        } # trimlogs always called -> samples_removed_from_raw.csv
		# final annotations always called "train_val_test_split_annotations.csv"
	```
	(See default example -> src/data_set/scrub_conditions.py)

3) analyze_data_splits.py
	- 
	- Behavior:
		- Reads data passed in from a config file (default or --config <config.py>), prompts user for a routine of different analyses to conduct. (e.g. histogramming labels, calculating variance etc)
		- Performs each requested analysis and saves in a folder of the root directory configured

	- Configuration fmt
	```python
	CONFIG = {
        "annotations_path" : "final_data/train_val_test_split_annotations.csv",
        "target_columns" : ["ncircles", "nbig", "nsmall"],
		# labels to perform analysis on 
        "analysis_write_path" : "DataDiagnostics",
		# root folder to save each analysis
        "feature_transform" : None
		# DataLoader img feature transform 
        } # Training schedule and configs are piped through input filesn
	```

4) train_models.py
	- 
	- Behavior:
		- Performs training according to the --model and --config options passed. When no --model is passed, prompts user for choice of models from currently implemented architectures.
		- Currently supports one epoch style that trains models according to the training set / optimizer / loss passed, then periodically evalutes the model updates on the validation set, saving the result if its better than the last validation check.  
		- Writes logging data for model trained based upon epoch routine

	- Configuration fmt:
	```python
	CONFIG = {
        "data" : {
            "final_annotations_path" : "final_data/train_val_test_split_annotations.csv", 
			#^ adjust to split_data settings
            "target_columns" : ["ncircles"], # list["str"] (what we're training for)
            "feature_transform" : None, # function object
            "batch_size" : 256, # int (configures each dataloader)
            "num_workers" : 4, # int, adjust to num procs available
            },
        "training" : {
            "loss" : nn.MSELoss(), # instance constructor call,
            "optimizer" : torch.optim.Adam, # CLASS (NOT CALL),
            "optimizer_params" : {"lr" : 0.001}, # args for optimizer class chosen, (the non-model.parameters() args)
            "logging_path" : "train_stats",
            "epoch_name" : "best_checkpoint_epochs", # < This is the only one
			#^ Can be Ask or registered ID in epochs register,
            "epoch_params" : {"n_epochs" : 100, "validation_interval": 10}, 
            },
        }

	```
5. analyze_models.py
	- 
	- Behavior:
		- Loads a model and evaluates it against several objectives in the test/train/validation splits of the data passed.
		- Prompts user for a schedule of analyses and any analyses hyper parameters required to evaluate objectives in a streaming fashion. (models make inferences once per batch, inferences are re-used per-objective) 
		- Logs each analysis result in <analysis_type>/.xvg/.json files, nested in the root logging path configured 
	- Config fmt
	```python
	CONFIG = {
        "model" : {
            "type" : "BasicLinear", 
			# ^ ModelFactoryKey string or "Ask" for prompt
            "meta_path" : "intro_experiment/set_a/LeastSquaresResults/cpt_meta_data/BasicLinear_step_0.json", 
			#^ meta_data written by Trainer class. or "Ask" for prompt
			#  (generally put your last latest which will vary dependent on data gen process)
            },
        "data" : {
            "annotations_path" : "intro_experiment/set_c/final_data/" + "train_val_test_split_annotations.csv",
			# ^ path to evaluation data annotation 
            "target_columns" : ["ncircles"],
			# ^ data labels we want to perform analysis on
            "feature_transform" : None
            },
        "analysis_settings" : {
            "evaluation_objective" : "ncircles", # str, colname
			# ^ which data label to grade the model agenst
            "log_path" : "intro_experiment/set_a/ModelEvaluation/set_c", # Results stored under modename in outside folder
            } # Currently the schedule must be piped in via the CL interface
        }
	```

- (SANITY STEP). direct_linear_model_solver.py
	- 
	- Behavior:
		- Has no default config options, a --config file must be passed 
		- Prompts user for one of three hard coded model choices (BasicLinear, RotatedLinear, Constant) that can be directly parameterized through linear least squares regression. 
		- logs the optimized parameters and confirms torch loss / linalg agree
		- prints the largest value of the hessian matrix associated with the least squares (MSE) loss function, along with theoretical maximum training step size for stability.

	- Configuration fmt:
	```python
	CONFIG = {
        "data" : {
            "annotations_file" : "intro_experiment/set_a/final_data/" + "train_val_test_split_annotations.csv", 
			#^ adjust to prior split_config file employed
            "target_columns" : ["ncircles"], # list["str"]
            "feature_transform" : None
            },
        "training" : {
            "logging_path" : "intro_experiment/set_a/", 
			# ^ direct_linear creates folder LinearLeastSquaresResults,
			#  we just provide the root
            },
        }
	```
